## 一、项目整体架构概览

### 技术组件清单（全部使用 Cloudflare 免费服务）

1. **前端静态页面（地图展示、提交表单）**：Cloudflare Pages

2. **后端 API 接口（接收提交、查询点位）**：Cloudflare Worker

3. **持久化数据存储（地点数据库）**：Cloudflare D1（SQLite 云数据库）

4. **AI 推荐扩展预留层**：Worker 中转第三方大模型 API（DeepSeek / 豆包 API）

5. **域名方案**

    - 测试分享：Pages 免费二级域名 `xxx.pages.dev`

    - 正式传播：独立域名接入 Cloudflare 解析（可选付费购买）

6. **地图底图**：高德 / 天地图国内开源瓦片底图（保障中国大陆正常加载）

## 三、分步详细实施操作流程

### 阶段 1：注册并准备 Cloudflare 账号

1. 访问 `dash.cloudflare.com` 注册免费个人账户

2. 确认免费套餐权限：Pages 静态托管、Workers 每日 10 万请求额度、D1 数据库免费额度（100 万行数据）

3. 记录账号信息，准备后续创建各项云资源

### 阶段 2：创建 D1 数据库（存储全部打卡点位）

1. 在控制台找到【D1 SQL Database】，新建数据库，自定义名称

2. 编写数据表结构（字段规划）

    - id：唯一编号

    - name：地点名称

    - lng /lat：经度、纬度坐标

    - category：地点分类标签

    - description：地点描述

    - image\_url：图片链接（预留）

    - create\_time：提交时间

    - status：审核状态（待审核 / 已上线）

3. 在 D1 网页控制台执行 SQL 语句完成建表

4. 记录数据库绑定标识，后续对接 Worker 后端

### 阶段 3：创建 Cloudflare Worker 后端服务

1. 菜单选择【Workers \& Pages】→ 创建 Worker 服务，自定义服务名称

2. 使用网页内置在线编辑器编写后端逻辑（后续写代码）

3. 绑定刚刚创建好的 D1 数据库，授权 Worker 读写数据表

4. 规划两套基础 API 接口

    - GET `/api/spots`：获取审核通过的全部公开点位数据

    - POST `/api/spots`：接收前端表单提交的新地点数据存入数据库

5. 保存部署 Worker，记录生成的后端访问地址

### 阶段 4：前端页面开发规划（本地编写，部署至 Pages）

1. 本地开发工具准备：安装 VS Code 编辑器，在电脑本地新建独立项目文件夹

2. 前端页面文件规划

    - `index.html`：主地图页面

    - 样式文件：控制布局、弹窗、表单样式

    - JS 脚本：地图初始化、加载高德底图、请求后端点位、添加标记、提交表单

3. 本地调试流程：双击打开 html 文件在浏览器预览地图效果，调试标记、弹窗、表单逻辑

4. 前端与后端对接：前端 JS 请求 Worker 生成的 API 地址实现数据读写

### 阶段 5：前端部署到 Cloudflare Pages（3 种可选上传方式）

方案 1｜拖拽上传（最简单新手方案）

1. Pages 控制台创建新项目

2. 选择直接上传静态文件

3. 选中本地整个项目文件夹上传部署

4. 部署成功后自动生成免费二级分享链接

方案 2｜Git 仓库自动部署（适合长期迭代更新）

1. 代码上传 Gitee/Github 仓库

2. Pages 绑定代码仓库，每次修改提交自动重新发布新版本

方案 3｜Wrangler 命令行部署（适合批量自动化更新）

### 阶段 6：基础测试与内测分发

1. 使用 pages\.dev 免费链接分享给小范围社区内测

2. 测试功能清单：

    - 新增地点提交功能是否生效

### 阶段 7（可选）：绑定自定义独立域名（适合长期社区传播）
