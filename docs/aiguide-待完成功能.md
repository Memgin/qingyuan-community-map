## 二、未完成 / 待实现（❌ / ⚠️）

### ❶ 推荐路线的数据库持久化（❌）
- 现状：暂存用 localStorage（**仅本机**），换设备 / 清浏览器数据即丢。
- 待做：保存为「我的路线」（DB 表 + 接口），支持重命名、删除、跨端同步（与鸿蒙 App 共享）。

### ❷ AI 结构化返回点位（❌，健壮性缺陷）
- 现状：靠"AI 文字里出现点位名称"反查 `spotIds`——AI 改写名称、用简称 / 别名 / 类别词就会**漏匹配 / 误匹配**（如"笔架山"被写成"笔架山森林公园"）。
- 待做：让 AI **直接返回结构化结果**（点位 `id` 列表或 JSON：`{ recommendation, spots: [{id, reason}] }`），前端按 `id` 精确取点，不再做字符串包含匹配。

### ❸ 路线顺序的真实路网优化（❌）
- 现状：`orderRouteSpots` 是简单曼哈顿距离贪心；编辑器已支持**手动调序**弥补，但自动排序仍未考虑实际路网距离 / 单行 / 跨江。
- 待做：接入高德路径规划 API 算真实顺序（作为编辑器的初始建议顺序）。

### ❹ 推荐结果与点位列表 / 详情联动（❌）
- 现状：路线序号标记点击**不联动**主地图飞行定位、不打开点位详情、不高亮列表项（编辑器清单同样未绑定点击飞行）。
- 待做：序号 `Marker` / 编辑清单项点击 → 主地图 `setZoomAndCenter` + 打开详情。

### ❺ 起终点 / 必经点指定（❌）
- 现状：贪心固定从首点出发，编辑器只能整体调序。
- 待做：编辑器支持「设为起点 / 终点 / 必经点」，重排时锚定这些点。

### ❻ 多路线 / 多日游管理（❌，未涉及）
- 一次推荐只产出一条线；无"另存为方案 A/B""第一天 / 第二天"等管理。

### ❼ 路线分享 / 导出（❌，未涉及）
- 无生成分享链接（私人地图已有分享机制可复用）、图片导出、或导入他人路线。

## 三、下一步建议顺序

1. **❷ AI 结构化返回**：低成本、高收益，直接消除漏匹配（可顺带解决路线编辑器里的点位准确性）。
2. **❶ 数据库持久化**：把暂存升级为「我的路线」，与私人地图模块的协作 / 分享体系打通。
3. **❹ 序号联动**：编辑清单与序号标记点击飞行 + 开详情，小改动大体验。
4. ❺❻❼ 按需推进。
